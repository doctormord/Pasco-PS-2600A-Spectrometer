\section{Overview}
This program turns four different spectrometers into one consistent
instrument. The same window (and the same numbers) work whether you have a
PASCO PS-2600A CCD on USB, an Ocean Optics HDX, an ASEQ/Lasertack LR-2T, or no
hardware at all (the built-in \emph{Demo (virtual)} device). Every USB protocol
was reverse-engineered from scratch; there are no vendor SDKs in the loop.

\medskip
The front-ends share one Qt-free engine (\S\ref{sec:architecture}):
\begin{itemize}
  \item \textbf{Desktop} --- \file{PS-2600A\_Pro.py}, a PyQt6 + pyqtgraph GUI.
  \item \textbf{Web} --- a FastAPI + WebSocket server with a browser client
        (\file{static/index.html} / \file{app.js} / \file{styles.css}, a uPlot
        scope and canvas-drawn heatmap\slash CIE\slash radar). It is started from the
        desktop app (\emph{Remote access}) or headless (\S\ref{sec:remote}).
  \item \textbf{REST API and MCP server} --- a versioned \code{/api/v1} for
        automated measurements, and an MCP server so that Claude can operate the
        instrument (\S\ref{sec:api}, \S\ref{sec:mcp}).
\end{itemize}
Because all of them call the identical engines (\file{color\_science.py},
\file{filter\_analysis.py}), a report exported from the web, the API or the
desktop contains the same values.

\medskip
\textbf{What it does:} live scope with overlays (CSV background reference,
freeze-to-grey, difference-vs-freeze, peak-hold envelope, persistence/afterglow);
a time-lapse heatmap (waterfall); CIE~1931 colorimetry
(CCT, Duv, $x,y$, $u',v'$, CRI~Ra + R1--R15); IES TM-30-18 (Rf, Rg, 16 hue bins,
colour-vector graphic, 99-sample fidelity) and CQS (Qa/Qf/Qg); optical-filter
characterization (transmission, type, peak/centre $\lambda$, FWHM, 50\,\% edges,
10--90\,\% edge steepness, blocking, optical density); PDF/PNG/CSV report export; a
25-spectrum reference library; dark-current correction; in-app calibration
(wavelength + response-profile wizards, per-device selection); auto-exposure; a
simple fast-preview mode; optional temporal and
spatial smoothing; and (web) a CSV waterfall replay player.

\subsection{How to run}
\begin{quote}\ttfamily\small
python PS-2600A\_Pro.py\hfill\# desktop GUI (entry point)\\
python PS-2600A\_Pro.py --headless\hfill\# engine + web UI + REST API, no Qt\\
python PS-2600A\_Pro.py --data-dir PATH\hfill\# other data directory (\S\ref{sec:datadir})\\
python web\_server.py\hfill\# same, historic entry point (forwards)\\
set FP\_DEBUG=1 \&\& python PS-2600A\_Pro.py\hfill\# Windows: per-frame fast-preview log
\end{quote}

\textbf{Dependencies} (\file{requirements.txt}): PyQt6, pyqtgraph, numpy, scipy.
Optional but recommended:
\begin{itemize}
  \item \textbf{matplotlib} --- CIE diagram fill and the PDF/PNG report renderers.
        Without it, CSV export still works; PDF/PNG return a hint.
  \item \textbf{colour-science} (\code{pip install colour-science}) --- enables the
        IES TM-30-18 and CQS sub-tab and \code{/api/tm30}. Everything else
        (CRI, CIE, reports minus TM-30) is unaffected if it is missing.
  \item \textbf{pyusb + libusb-package} --- Ocean HDX. \textbf{hid} --- LR-2T.
        PASCO needs WinUSB (via Zadig) on Windows.
\end{itemize}
The Demo device needs only numpy, so the application is always usable for
learning and testing with no hardware attached.

\section{System architecture}\label{sec:architecture}
All front-ends --- the desktop GUI, the web interface, the REST API and the MCP
server --- sit on one Qt-free core, the \code{Engine} (\file{engine.py}). The
engine owns the spectrometer, the acquisition threads, temporal smoothing and
frame averaging, the processing pipeline, the calibration runtime, the heatmap
buffer, the throttled colour metrics, the control ownership and the job system.
Front-ends never re-implement any of this; they only present it.

{\footnotesize
\begin{verbatim}
          +--------------------------------------------+
          | engine.py (no Qt)                          |
          |  Engine: device, fusion, averaging,        |
          |  processing, CalibrationRuntime, heatmap,  |
          |  colour metrics, jobs, control ownership   |
          +-----------+-----------------+--------------+
              listener|                 |listener
   +------------------+--+     +--------+----------------------+
   | GUI (PyQt6)         |     | api.py (FastAPI, no Qt)       |
   | Qt-signal bridge    |---->| create_app(engine, settings)  |
   | starts/stops server |     | REST /api, /api/v1, WebSocket |
   +---------------------+     +--------+----------------------+
                                        | HTTP + token
                               +--------+----------------------+
                               | mcp_server/ (stdio)           |
                               +--------+----------------------+
                                        |
                               Claude (plugin: agents, skills)
\end{verbatim}}
\captionof{figure}{Architecture. The engine publishes events to registered
listeners; the GUI attaches a Qt-signal bridge, the API server schedules sends on
its asyncio loop. Commands flow the other way, thread-safe and tagged with an
owner.}

\begin{itemize}
  \item \textbf{Engine and listeners.} \code{engine.subscribe(callback)} delivers
        \code{EngineEvent} objects (kinds: \code{frame}, \code{auto\_exposure},
        \code{config}, \code{connection}, \code{calibration}, \code{axis},
        \code{control}, \code{job}, \code{measurement}) from engine threads. Reads
        return snapshots or copies.
  \item \textbf{Qt-signal bridge.} The desktop window marshals every event to the GUI
        thread with a signal; only pure display logic (freeze, diff, peak-hold,
        persistence, overlays) stays in \file{gui\_dashboard.py}.
  \item \textbf{API hub.} \file{api.py} (\code{create\_app(engine, settings)}) keeps
        no device state. A hub forwards engine events to the WebSocket clients
        with \code{asyncio.run\_coroutine\_threadsafe}.
  \item \textbf{Control ownership.} The engine knows one controlling party at a
        time: \code{local} (the desktop), \code{web} or \code{remote:<client>}. A
        job or an explicit lease holds control; a conflicting steering command
        gets HTTP~409, the desktop locks its controls (\S\ref{sec:remote}).
  \item \textbf{Jobs.} Single measurement, series, dark capture, calibration run and
        derivation run as jobs with an ID, status, progress and result. They
        acquire raw frames through frame taps (\file{calibration\_capture.py}), not
        through the display pipeline.
\end{itemize}

\subsection{Hard rules (why the code is shaped this way)}
\begin{itemize}
  \item \textbf{All device-specific code lives in its \file{\_device\_*.py} file.}
        \file{spectrometer\_core.py} holds only app-wide constants, the reference
        library and context help.
  \item \textbf{No PyQt in the core.} \file{engine.py}, \file{api*.py},
        \file{server\_runner.py}, \file{wavelength\_calibration.py},
        \file{mcp\_server/} and every module they import must not import PyQt, not
        even indirectly (a test enforces this). That is what makes
        \code{--headless} run without Qt installed.
  \item \textbf{One device = one engine.} A device is opened by exactly one
        \code{Engine} instance; the desktop app and a separate headless server
        cannot use the same device at the same time (one process per device).
  \item \textbf{Logic exists once.} Desktop and web differ only in presentation;
        existing \code{/api/...} and \code{/ws/stream} endpoints keep path and
        format, new functions go under \code{/api/v1}.
  \item \textbf{Science/signal processing is device-agnostic}
        (\file{fusion.py}, \file{processing.py}, \file{color\_science.py},
        \file{filter\_analysis.py}) --- never inside a driver. Drivers acquire and
        tag frames; processing and science decide display and metrics.
  \item A new device is a new \file{\_device\_xxx.py} implementing
        \code{BaseSpectrometer}, registered in \code{device\_manager.build\_registry()},
        with its config keys added to \code{DEFAULT\_CONFIG}.
  \item The three hardware drivers are deliberately parallel in structure and
        method order, so a new one can be cloned from any of them.
\end{itemize}

\subsection{The frame data path}
\begin{enumerate}
  \item The driver acquires a frame and (if Fast Preview is on) has already scaled
        the short exposure back up to the main-exposure level.
  \item It calls \code{on\_frame(pixels, dark, integration\_us, kind, ratio)} --- a
        single, finished, displayable frame.
  \item \code{SpectrumFusion.submit()} optionally applies adaptive temporal
        smoothing (if the ``Smoothing'' section is enabled).
  \item The engine runs the processing pipeline (\file{processing.py}), updates the
        heatmap buffer and the throttled colour metrics, and publishes a
        \code{frame} event.
  \item Listeners receive it: the desktop (via the Qt-signal bridge, on the GUI
        thread) fans it out to Scope, Heatmap, Color (+CRI/TM-30) and Filter; the
        API hub sends it to the WebSocket clients.
\end{enumerate}
Jobs (measurements, series, calibration) bypass the display pipeline: they read
raw frames through frame taps on the driver, so their result does not depend on
the live view settings. The fusion emit stage keeps the canvas fluid even when new measurements
arrive slowly, but it cannot invent new data --- the \emph{new-data} rate is set by the exposure
(\S\ref{sec:perf}).

\subsection{The \code{BaseSpectrometer} interface}
Every driver subclasses \code{BaseSpectrometer} and exposes the same shape, so the
front-ends never special-case a device:
\begin{itemize}
  \item \textbf{Class attributes:} \code{PIXEL\_COUNT}, \code{WL\_MIN\_NM},
        \code{WL\_MAX\_NM}, \code{SUPPORTS\_OB}, \code{SUPPORTS\_FAST\_PREVIEW},
        \code{RESPONSE\_TABLE}.
  \item \textbf{Instance attributes:} \code{min\_integration\_us} /
        \code{max\_integration\_us} carry the connected device's exposure bounds,
        set in \code{connect()} from config or hardware constants; the GUI spinbox
        and web clamps read them, so the exposure control always follows the
        connected device. \code{serial} holds the device serial when known.
  \item \textbf{Methods (in order):} \code{scan()} $\to$ \code{connect(device\_id)}
        $\to$ \code{start()} $\to$ \code{stop()} $\to$ \code{disconnect()} $\to$
        \code{set\_integration\_time\_us(us)} $\to$ \code{wavelength\_array}
        property $\to$ \code{calibrate\_from\_lines()} $\to$ hardware helpers $\to$
        \code{\_run()}.
\end{itemize}

\paragraph{Frame callback contract.}
\code{on\_frame(pixels, dark, integration\_us, kind="standard", ratio=1.0)}. Every
driver forwards a \emph{finished}, displayable frame as a standard frame with
\code{ratio=1.0}. With Fast Preview on, the driver has already shortened the
exposure and scaled the net signal up to the main-exposure level, clipped to
saturation and re-added dark. The \code{kind}/\code{ratio} parameters survive only
for signature compatibility.

\paragraph{PASCO special pattern.}
\code{PascoPS2600A} wraps a \code{SpectrometerAcquisition} \code{QThread}; its
runtime flags (pause, auto-exposure, fast-preview) are Python properties whose
setters write into the running thread object. LR-2T and HDX run \code{\_run()} on
\code{self}, so plain attributes suffice.

\subsection{Integration-time bounds (per device)}
\code{device\_constants.GLOBAL\_MIN/MAX\_INTEGRATION\_TIME\_US} are only an absolute
sanity backstop (minimum $100\,\um$). The real per-device limits come from each
back-end: Ocean and LR-2T read \key{ocean\_*} / \key{lr2t\_min/max\_integration\_us}
from config (so the HDX can be pushed below its $6\,$ms default --- verify per
firmware that the metadata exposure follows and frames do not NACK); PASCO uses its
fixed hardware constants ($1\,$ms\,/\,$2.5\,$s). Each back-end publishes the
resolved values through \code{min\_integration\_us} / \code{max\_integration\_us}.

\section{Pixel\,$\leftrightarrow$\,wavelength mapping \& calibration}
\subsection{Polynomial mapping}
Pixel index $i$ (0-based) maps to wavelength by a cubic polynomial
\[
\lambda(i) = C_0 + C_1 i + C_2 i^2 + C_3 i^3 ,
\]
implemented in \code{calibration\_utils.poly\_wavelength\_array}
(via \code{np.polyval} on the reversed coefficients). For the bench PASCO unit:
\[
\lambda(i) = 75.452 + 0.3458\,i - 2.337\times10^{-5} i^2 + 1.226\times10^{-9} i^3 ,
\]
fitted from Cadmium lines at 467.8 / 480.0 / 508.6 / 643.8\nm (Fig.~\ref{fig:fig_mapping.pdf}).

\fig{fig_mapping.pdf}{0.98}{Left: the PASCO pixel$\to\lambda$ cubic with the four
Cd calibration lines marked. Right: the reciprocal linear dispersion
$\mathrm{d}\lambda/\mathrm{d}px$ across the array.}

\subsection{Calibrating from known lines}
\code{calibration\_utils.fit\_wavelength\_polynomial(pixel\_positions,
wavelengths\_nm, degree)} fits coefficients (and returns the residuals) from a set
of peak-pixel / known-wavelength pairs --- e.g.\ Neon lines at
585.2 / 640.2 / 667.8 / 703.2\nm. Use Cd, Ne or Ar discharge lamps, read the peak
pixel of each known line, and fit a degree-3 polynomial. A fine offset can be
applied afterwards with \code{apply\_wl\_offset} (config keys
\key{lr2t\_wl\_offset\_nm}, \key{ocean\_wl\_offset\_nm}); a positive offset shifts
the displayed spectrum toward red.

\subsection{The wavelength wizard (desktop)}\label{sec:wl-wizard}
\emph{Processing\,\textperiodcentered\,06 $\to$ Calibration\ldots\ $\to$
Wavelength} drives the fit above interactively (\file{gui\_calibration.py},
device-agnostic helpers in \file{calibration\_profiles.py}). Pick a lamp ---
curated NIST line lists for Hg, Cd, Ne, Ar, He, Kr, Xe, Na and H are built in ---
and \emph{Capture \& detect}: the wizard averages
\key{calibration\_capture\_frames} frames (see \S\ref{sec:cal-capture}), finds
peaks to sub-pixel precision (parabolic interpolation, $\sim$0.03\,px) and
auto-pairs them with the known lines on the current axis. Edit the
pixel\,$\leftrightarrow\lambda$ table if needed, then \emph{Fit \& apply} (live on
the scope) and \emph{Save to device}, which persists the coefficients to
\key{pasco\_wl\_poly\_coeffs} / \key{lr2t\_wl\_poly\_coeffs} /
\key{ocean\_wl\_poly\_coeffs} (\code{null} = factory axis); the driver reloads them
on the next connect.

\textbf{Residuals are not the whole truth.} The wizard reports the max and RMS
residual \emph{at the fitted lines}, but a degree-3 polynomial constrained only in
the middle of the array (e.g.\ by the four visible Cd lines, 467.8--643.8\nm)
extrapolates badly toward the ends while still showing near-zero residual at the
lines. The wizard prints an explicit \emph{coverage warning} when the line span
leaves a large part of the device range unconstrained --- combine lamps
(Hg + Ne + Ar) for a trustworthy full-range solution.

\subsection{Per-device wavelength sources}
\begin{itemize}
  \item \textbf{PASCO} --- fixed polynomial above (no on-device coefficients).
  \item \textbf{Ocean HDX} --- wavelength and nonlinearity coefficients are read
        \emph{from the device} at connect time. \key{ocean\_use\_device\_wavelength}
        chooses device coefficients vs.\ a linear fallback
        (\key{ocean\_wl\_fallback\_min/max\_nm}); \key{ocean\_nonlinearity\_correction}
        applies the device polynomial.
  \item \textbf{LR-2T} --- device wavelength mapping plus \key{lr2t\_flip\_pixels}
        (set true only if the spectrum appears mirrored after connecting) and the
        offset key above.
\end{itemize}

\subsection{Dark-current correction}
Two models, selected by \key{dark\_mode}:
\begin{itemize}
  \item \textbf{Optical black} (PASCO) --- the 30 masked ``optical black'' pixels
        give a live dark reference; an OB slope/offset
        ($1.00818$ / $-0.6377$ for the bench unit) maps OB mean to the dark level.
  \item \textbf{Parametric} --- $\text{dark} = \text{bias} + \text{rate}\cdot t$,
        with \key{dark\_bias\_adc} and \key{dark\_rate\_adc\_per\_s}
        (bench PASCO: $61.57\,$ADC and $40.94\,$ADC/s at 22\textdegree C).
  \item \textbf{HDX / LR-2T} --- the dark level is estimated as the median of the
        \key{ocean\_dark\_estimate\_pixels} (default 50) darkest pixels each frame.
\end{itemize}
Dark correction is applied in \file{processing.py}, not in the drivers, and is only
subtracted when \key{dark\_correction} is enabled.

\subsection{Spectral-response correction \& profiles}\label{sec:response}
A response table (\code{[wavelength\_nm, sensitivity]} pairs, sensitivity
normalised to 1.0 at peak) becomes a per-pixel gain via
\code{calibration\_utils.build\_response\_gain}
($\text{gain} = \min(1/\text{sensitivity}, \text{max\_gain})$, interpolated onto
the pixel axis); multiplying raw counts by it flattens the instrument response.
Unlike wavelength, this is genuinely \emph{per fibre / optical setup} (it folds in
detector QE, grating efficiency, optics \emph{and} fibre transmission), so it is
stored as \emph{named, selectable profiles} per device.

\emph{Note: the generic relative\,/\,absolute calibration with lamp library, versions and protocol is described in \S\ref{sec:speccal}; the wizard below is the legacy route (tab ``Response (legacy)'').}

\paragraph{The response wizard (desktop).} \emph{Calibration\ldots\ $\to$
Response} measures a SMOOTH BROADBAND lamp (halogen, white LED --- never a line
lamp) on the device under test and divides it by a reference of the \emph{same}
lamp, captured live (e.g.\ on a reference spectrometer) or loaded from a CSV:
\[
  S(\lambda) = \frac{\text{measured}_{\mathrm{norm}}(\lambda)}
                    {\text{reference}_{\mathrm{norm}}(\lambda)} .
\]
\emph{Compute} previews $S$; \emph{Save profile} stores it and selects it.
\code{calibration\_profiles.compute\_response\_table} builds a \emph{full-axis}
table: measured $S$ where the reference is reliable (above
\key{ref\_floor\_frac}, default 5\,\% of its peak), and sensitivity $=1.0$
(\emph{no correction}) everywhere else, so dark gaps and bare edges are never
amplified. $S$ is peak-normalised by its 98th percentile (noise-spike-proof) and
lightly smoothed (edge-coverage-normalised). Coverage $<60\,\%$ raises a
\emph{banded-source warning} --- a line/band lamp (e.g.\ a fluorescent) is the
wrong reference and yields no meaningful correction away from its bands.

\paragraph{Selecting a correction.} The sidebar \emph{Response correction}
drop-down (it replaced the old on/off toggle) chooses per device: \emph{None}
(gain $\equiv 1$, unchanged behaviour), \emph{Device default} (the driver's
built-in \code{RESPONSE\_TABLE}, offered only where one exists --- currently the
PASCO datasheet approximation), or a saved profile. Switching applies live. The
selection persists per device in \key{response\_correction\_active}
(\code{\{device: selection\}}); the legacy boolean
\key{spectral\_response\_compensation} is kept in sync automatically, so
\file{processing.py} needs no awareness of profiles. Profile tables live in a
separate registry, \key{calibration\_profiles\_file}
(\file{calibration\_profiles.json}). The web client mirrors the dropdown
(\code{/api/calibration/profiles}, \code{/select}, \code{/profile/delete});
profiles are \emph{created} only in the desktop wizard and shared via the registry.

\paragraph{Honest limits.} Outside a table's measured range
\code{build\_response\_gain} returns gain $1.0$ (no correction), never
\code{max\_gain} --- a previous \code{min\_floor} fill there multiplied the bare
noise floor by $\sim$10$\times$ across every uncovered pixel (lifting the whole red
region and spiking the UV edge for a banded source). A cross-device profile
matches the device to the \emph{reference's} shape (instrument difference $+$
fibre folded together), not to an absolute scale, and not to ``pure fibre
transmission'' --- for that, measure the same device with and without the fibre so
its response cancels. Never chain calibrations (calibrating against an
already-corrected reference): errors add in quadrature and clamp artefacts bake
in. A self-calibration sanity check (reference $=$ measurement) yields gain
$\approx 1.0$ everywhere.

\subsection{Capture averaging}\label{sec:cal-capture}
Every wizard capture averages \key{calibration\_capture\_frames} (default 16)
\emph{genuinely new} frames, counting noise down by $\sqrt{N}$. The capturer
detects duplicate polls (the live snapshot is sampled faster than the frame rate)
via array comparison and skips them, so the $\sqrt{N}$ holds regardless of frame
rate. This matters more for the response correction than for the filter baseline,
because a response divides two measured spectra (errors add in quadrature,
amplified by $1/S$ at weak edges). Captures use the dark-corrected,
response-\emph{un}corrected spectrum --- a calibration must measure the
instrument, not a previous correction.

\subsection{Absolute radiometric calibration}
\emph{Superseded by the spectral absolute calibration (\S\ref{sec:speccal}); the scalar below is used only without an absolute profile.}\\
\key{radiometric\_calibration\_factor} is the scale (W/m\textsuperscript{2}/nm per
ADC count) used to turn counts into absolute irradiance and thus lux / foot-candle
readings. $0.0$ means \emph{uncalibrated} --- lux displays show ``\,--\,''. Derive
it by measuring a lamp of known spectral irradiance at a known distance and fitting
the scale factor.

\section{Spectral calibration (relative \& absolute)}\label{sec:speccal}
This chapter describes the generic calibration process that is identical for
every back-end (PASCO PS-2600A, Ocean HDX, ASEQ LR-2T, Demo) and for any input
optic. The computation lives in device-agnostic modules
(\file{calibration\_profiles.py}, \file{calibration\_capture.py},
\file{calibration\_workflow.py}, \file{reference\_sources.py},
\file{calibration\_report.py}, \file{processing.py}); there are no device
special cases outside the drivers. Without an active profile the behaviour is
unchanged (\S\ref{sec:speccal-profiles}).

\subsection{Terms}
\begin{longtable}{@{}p{3.6cm}p{10.6cm}@{}}
\toprule \textbf{Term} & \textbf{Meaning}\\ \midrule\endhead
Wavelength calibration & Pixel $\to\lambda$ polynomial of the \emph{device}
  (\S\ref{sec:wl-wizard}), unit nm.\\
Relative calibration & Sensitivity $S(\lambda)$, peak $=1$. Output is
  proportional to spectral irradiance (unit: \emph{relative}). Valid for device
  + optics configuration.\\
Absolute calibration & Factor $K(\lambda)$; output is spectral irradiance in
  $\mu$W/(cm$^2$\,nm) (\code{uW/cm2/nm}) or W/(m$^2$\,nm). Needs
  an input optic with a defined entrance area (CC or sphere).\\
Optics configuration & Freely named combination of fibre, input optic and
  connector. Any configuration can be recalibrated at any time; every run
  creates a new profile version.\\
Input optic & \code{CC} (cosine corrector), \code{bare} (bare fibre) or
  \code{sphere}. \code{bare} is \emph{always relative}.\\
Reference source & A calibrated lamp (e.g.\ HAL-CAL) stored as \emph{data} in the
  lamp library: name, serial number, unit, lower/upper validity limit,
  intended input optic.\\
Profile & One stored calibration result (schema~2): type, device, optics,
  reference, table, valid range, checks, timestamp.\\
Version & Counter per series (device, optics, type). The newest \emph{valid}
  version is the default; older versions remain available.\\
Fingerprint & Hash of the wavelength axis stored in each profile; $S$ and $K$
  contain the pixel width in nm, so a changed axis invalidates them.\\

  made on. A second unit of the same type does not list it.\\
\bottomrule
\end{longtable}

\subsection{Physics and formulas}
All calibration and measurement data are referred to the count rate
\[
  C(\lambda) = \frac{\mathrm{raw}_{\mathrm{lin}}(\lambda) - \mathrm{dark}(\lambda)}{t_{\mathrm{int}}}
  \quad[\mathrm{counts/s}] ,
\]
with the linearised raw data, a \emph{per-pixel} dark spectrum taken at the same
integration time, and the mean over $N$ frames. $S$ and $K$ are thereby
independent of integration time and averaging. Negative values are not clipped
in the calibration path.

\paragraph{Relative.}
$S(\lambda) = C_{\mathrm{cal}}(\lambda)/E_{\mathrm{ref}}(\lambda)$, normalised to
a peak of 1 (after an optional small moving average, \key{calibration\_smooth\_px}).
Correction: $C/S$.

\paragraph{Absolute.}
$K(\lambda) = E_{\mathrm{ref}}(\lambda)/C_{\mathrm{cal}}(\lambda)$; measurement
$E(\lambda) = C(\lambda)\cdot K(\lambda)$. The relative profile derived from an
absolute one ($S\propto 1/K$, peak 1) is saved as well.

\paragraph{Reference and units.}
The reference table is interpolated onto the pixel axis by monotone PCHIP
(no overshoot). Units: $1\,\mu\mathrm{W}/(\mathrm{cm}^2\,\mathrm{nm}) =
0.01\,\mathrm{W}/(\mathrm{m}^2\,\mathrm{nm})$; lamps may also be delivered in
mW/(m$^2$\,nm). Illuminance (lux) is computed directly from $E(\lambda)$
(\S\ref{sec:speccal-apply}).

\subsection{Valid range and masking}
The valid range is the \emph{intersection} of
\begin{itemize}
  \item the device display limits (\code{spec\_range\_nm()} /
        \key{<device>\_spec\_min\_nm}, \key{\_max\_nm}),
  \item the defined range of the reference source (lower limit configurable per
        source; HAL-CAL: 380\nm),
  \item pixels with sufficient signal: $C_{\mathrm{cal}} > k\cdot\sigma_{\mathrm{dark}}$
        (\key{calibration\_snr\_k}, default 10),
\end{itemize}
and excludes saturated pixels (any frame at or above the backend's ADC full scale)
and pixels whose gain would exceed \key{calibration\_max\_gain}
($S<1/\mathrm{max\_gain}$). Pixels that fail the per-pixel stability or cross
check (\S\ref{sec:speccal-checks}) are masked as well and limit the valid
segments. Outside the valid range the output is \emph{masked}
(NaN, drawn grey in the plot); it is never continued with gain~1. A calibration
is refused if the calibration spectrum contains saturated pixels or if no valid
pixel remains.

\subsection{Procedure}\label{sec:speccal-wizard}
\paragraph{Preparation (identical for every device and optic).}
(1)~Calibrate the wavelength axis with line lamps (e.g.\ Cd and Hg) over the whole
display range; do not change it afterwards, otherwise recalibrate the
response. (2)~Define and name the optics configuration; do not disconnect fibres
or connectors until the series is finished. (3)~Warm up device and lamp.
(4)~\emph{Absolute:} mount the input optic with a defined area (CC) in the
lamp setup for which the lamp's calibration is valid. \emph{Relative, bare
fibre:} centre the fibre reproducibly in the lamp port (adapter sleeve) or derive
the profile (\S\ref{sec:speccal-derive}).

\paragraph{Wizard} (\emph{Calibration\ldots\ $\to$ Spectral calibration}, fixed
sequence, identical for every device):
\begin{enumerate}
  \item Choose device, optics configuration (new or existing), input optic,
        reference source from the library and type (relative\,/\,absolute;
        absolute only for input $\neq$ bare).
  \item Check that a wavelength calibration exists (fingerprint); warnings for
        the factory linear axis or for changes since the last run.
  \item Set the integration time or use auto-exposure to the target band
        (\key{calibration\_target\_frac\_lo/hi}, default 70--85\,\% of full scale);
        it is then fixed.
  \item \textbf{Dark spectra before.} Both dark spectra ($t_{\mathrm{int}}$ and
        $\approx t_{\mathrm{int}}/2$ for the cross check) are taken in
        \emph{one} covering step. Devices without a shutter ask you to cover the
        input and to uncover it afterwards.
  \item Capture the calibration spectrum and, after
        \key{calibration\_stability\_delay\_s}, the repeat capture
        (stability).
  \item Capture at $\approx t_{\mathrm{int}}/2$ (integration-time cross check).
  \item \textbf{Dark spectra after}, again at $t_{\mathrm{int}}$ and
        $t_{\mathrm{int}}/2$ in a second covering step. Every light capture is
        corrected with the dark \emph{interpolated in time} between its dark
        before and after (\S\ref{sec:speccal-dark}).
  \item Automatic \emph{per-pixel checks} (stability and cross check) with
        cause analysis (\S\ref{sec:speccal-checks}).
  \item Compute $S$ or $K$, valid range, plausibility including the gain-span
        hint (\S\ref{sec:speccal-gainspan}); display $C_{\mathrm{cal}}$,
        $E_{\mathrm{ref}}$, result and warnings.
  \item Save as a new profile version (absolute: plus the derived relative
        profile) and create the calibration protocol.
  \item \textbf{Verification} (\S\ref{sec:speccal-verify}): the reference lamp is
        measured through the live pipeline with the new profile.
\end{enumerate}

\subsection{Dark before and after, interpolation, drift}\label{sec:speccal-dark}
The dark level of some detectors (LR-2T) jumps between runs by tens to hundreds
of counts; a single dark taken once therefore leaves a constant count offset in
the calibration. The wizard takes the darks \emph{before} and \emph{after} the
light captures. For each light capture the dark is interpolated \emph{per pixel,
linearly in time} between the dark before and the dark after, evaluated at the
capture's mid time (without usable time stamps the mean of both; without a dark
after, the dark before). The change of the dark level between before and after
is reported as \emph{dark drift}: mean over the pixels (counts), its expected
noise, the 95th percentile of the per-pixel change and the elapsed time. A mean
drift well above its noise ($>3\sigma$) and above
\key{calibration\_dark\_drift\_warn\_pct} (default 0.5\,\%) of the net peak signal
produces a warning and is recorded in the protocol.

\subsection{Per-pixel checks and cause model}\label{sec:speccal-checks}
Both checks compare two count-rate spectra \emph{per pixel}: the repeat at
$t_{\mathrm{int}}$ (stability) and the capture at $\approx t_{\mathrm{int}}/2$
(cross check, expected ratio 1 in count rate). A tested pixel passes if
\[
  \bigl|C_{\mathrm{test}} - r\,C_{\mathrm{ref}}\bigr| \le
  k\sqrt{\sigma_{\mathrm{ref}}^{2}+\sigma_{\mathrm{test}}^{2}}
  + \frac{p}{100}\,|C_{\mathrm{ref}}| ,
\]
with $\sigma$ the per-pixel standard deviation of the mean rate (dark and shot
noise of the actual captures), $r$ the expected ratio (1, or a lamp-drift
correction), $k=$ \key{calibration\_pixel\_check\_k} (default 4) and $p$ the
check threshold (\key{calibration\_stability\_threshold\_pct}, default 1\,\%;
\key{calibration\_itime\_threshold\_pct}, default 2\,\%). The noise term keeps
weak pixels from failing on noise alone; the relative term is the systematic
deviation the check accepts. Non-positive or non-finite rates fail. The
\emph{failing pixels are masked} and limit the valid segments; the number of
failing pixels per check is shown and recorded. (The earlier 95th-percentile
criterion over the signal-rich pixels could leave pixels with
$C_{\mathrm{half}}/C_{\mathrm{cal}}$ up to 1.75 or negative inside the valid
range.)

\paragraph{Cause model.} Over all tested pixels, in counts of the test capture
($x$ = counts expected from the reference rate, $y$ = measured counts), the
model
\[
  y = a + s\,x + c\,\frac{x^{2}}{\mathrm{FS}}
\]
is fitted by weighted least squares ($c=0$ for the repeat at the same
$t_{\mathrm{int}}$; one robust re-fit without outliers above $5\sigma$). A term
is reported as a cause when it is significant ($>3$ standard errors) \emph{and}
its effect on the ratio $y/x$ reaches \key{calibration\_cause\_min\_pct} (default
0.3\,\%). The message names the cause and its magnitude.
\begin{itemize}
  \item \textbf{Dark drift} ($a$, constant count offset): the dark level changed
        or does not match the dark used. Remedy: warm up the device, repeat the
        darks, check light leaks while covering.
  \item \textbf{Time offset} ($s\neq1$ in the cross check): the effective
        exposure differs from the nominal $t_{\mathrm{int}}$ by a constant
        (readout or shutter timing); uniform factor.
  \item \textbf{Lamp drift} ($s\neq1$ in the repeat at the same $t_{\mathrm{int}}$):
        the source changed between the two captures; let the lamp warm up. The
        stability result is applied as $r$ to the cross check.
  \item \textbf{Nonlinearity} ($c$, signal-dependent): the detector response is
        not proportional to the light. Remedy: linearity calibration
        (\S\ref{sec:linearity}).
\end{itemize}
A failed check produces a warning, not a block; it is recorded in the profile and
the protocol. If $t_{\mathrm{int}}$ cannot be halved (device minimum) the cross
check is skipped and noted.

\subsection{Gain span (hint)}\label{sec:speccal-gainspan}
The ratio of the largest to the smallest gain over the valid range is reported
as a \emph{hint} only: a halogen lamp on a silicon detector legitimately spans
50--100$\times$ between 380 and 950\nm. The default limit is 200$\times$
(\key{calibration\_max\_gain\_span}); a stored old default is replaced once by
the new one. Line sources and unsuitable references are recognised by the other
plausibility metrics: coverage of the expected range, roughness (95th percentile
of $|S/S_{\mathrm{smoothed}}-1|$), isolated peaks and the widest bridged
segment.

\subsection{Verification}\label{sec:speccal-verify}
After saving, the reference lamp (uncovered, same geometry) is measured
\emph{through the live pipeline} with the new profile (stored dark at the
profile's $t_{\mathrm{int}}$, same processing as the display). The corrected
spectrum is compared with the reference file, both normalised over
550--650\nm (\key{calibration\_verify\_norm\_lo\_nm/hi\_nm}). The result lists the
deviation in percent \emph{per 50\nm band} (\key{calibration\_verify\_band\_nm})
and overall (rms, maximum); bands beyond \key{calibration\_verify\_warn\_pct}
(default 2\,\%) are flagged. Absolute profiles are additionally compared
unnormalised. The verification can also be started later for any saved v2 profile
(web client, API \code{POST /calibration/verifications},
MCP tool \code{verify\_profile}). Typical bench result with the HAL-CAL lamp:
425--949\nm within $\pm1.2$\,\%, 400--425\nm about $+2$\,\%, 375--400\nm about
$+5$\,\% (low lamp output and stray light in the blue).

\paragraph{Reference overlay.} The reference curve can be shown in the scope
(\key{scope\_reference\_overlay}, \key{scope\_reference\_id}). With an absolute
display it is drawn unscaled in the display unit; in every other display mode it
is scaled by least squares onto the displayed values over the valid pixels.
(API: \code{GET /calibration/reference-overlay}.)

\subsection{Deriving one optic from another}\label{sec:speccal-derive}
The mode \emph{Derive from other optics} (tab \emph{Spectral calibration})
creates a profile for a new optics configuration (e.g.\ bare fibre) from a known
one (e.g.\ CC) via two measurements of the \emph{same source}:
\[
  S_{\mathrm{new}} = S_{\mathrm{known}}\cdot\frac{C_{\mathrm{new}}}{C_{\mathrm{known}}} ,
\]
with $C$ the count rates [counts/s] after linearisation and dark subtraction.
The result is always relative. The valid range is the overlap of the known
profile's range with the pixels of sufficient signal in both captures and
without a failed drift check.

\paragraph{Source.} A diffuse, uniformly luminous, extended target that fills the
field of view of \emph{both} optics, for example back-illuminated opal glass in
the object plane. Source, position and power must stay unchanged during the
whole run. The wizard shows this note in the derivation form and in the first
dialog of the run, and the protocol records it.

\paragraph{Own integration time per optics.} The brightness of two optics on the
same source can differ by orders of magnitude (bare fibre versus cosine
corrector). Each optics therefore has its \emph{own} integration time, either
\emph{Auto} (auto-exposure to the target band
\key{calibration\_target\_frac\_lo/hi} with that optics mounted and the source on)
or a fixed value in ms. Because $C$ is a count rate, the result does not depend on
the chosen times; both sides at the same level also keep the residual
nonlinearity equal. Every optics has its \emph{own dark spectra} at its own
integration time; dark and light of one optics always use the same integration
time (checked and recorded). The linearity correction of the unit is applied to
every capture; the wizard reports it (on\,/\,off\,/\,n/a) per optics and refuses to
mix captures with a changed correction.

\paragraph{Sequence.} The wizard lists the steps in this order; devices without a
shutter ask you to cover the input before each dark and to release it afterwards.
\begin{enumerate}
  \item Source note, mount the \emph{known} optics (light path open).
  \item Integration time of the known optics, dark, light.
  \item Mount the \emph{new} optics on the same source (light path open).
  \item Integration time of the new optics, dark, light, dark \emph{after}.
  \item Mount the known optics \emph{again}; measure it a second time
        (\emph{repeat}), then its dark after.
  \item Compute $S_{\mathrm{new}}$, plausibility, drift and consistency checks.
  \item Save (see below) and write the derivation protocol.
\end{enumerate}
Light captures are corrected with the dark of their optics interpolated in time
between dark before and after (\S\ref{sec:speccal-dark}). A capture with saturated
pixels stops the run with a message naming the affected optics; shorten its
integration time (or use Auto) and start again.

\paragraph{Source drift.} The repeat with the known optics compares, per pixel
and overall, the two known-optics captures (same time basis, same integration
time). Reported: 95th percentile of the smoothed ratio, mean ratio, the limit, the
status, the number of masked pixels, the elapsed time and a cause analysis. The
limit is \key{calibration\_derivation\_drift\_pct} (default 2\,\%); the per-pixel
test adds the noise-dependent tolerance (\key{calibration\_pixel\_check\_k}).
Failing pixels are masked and limit the valid segments. The known-optics count
rate used in the ratio is interpolated linearly in time to the capture of the
new optics, which compensates a linear drift.

\paragraph{Saving.} A result that fails the plausibility check is saved only after
explicit confirmation, is marked as not plausible and is not activated. A
plausible result whose drift or consistency check failed is saved only after the
question \emph{Checks failed\ldots\ Save anyway?}; answering \emph{No} leaves
the profile unsaved (the protocol is still written).

\paragraph{Protocol.} After every completed computation (also when it fails or is
not saved) a PDF and a CSV are written to the protocol folder; file name
\file{derivation\_device\_serial\_optics\_type\_timestamp}. Content: date and time
with time zone, device and serial number, known profile (id, version, optics), new
optics, source note; per optics integration time, auto\,/\,fixed, level in
\% FS (light and repeat), dark sequence, same-integration-time check and
linearity correction (on\,/\,off\,/\,n/a) plus the device NL correction; source
drift in total (p95, mean, limit, status, masked pixels, duration, cause) and per
pixel (chart with the $\pm$ limit); dark drift per optics; plausibility, valid
range and segments, gain span, warnings and saved profiles; charts of the
normalised count rates and of $S_{\mathrm{known}}$\,/\,$S_{\mathrm{new}}$. The
CSV (UTF-8) has a \code{\# key;value} header with the same fields and the columns
\code{Wavelength\_nm;C\_known\_cps;C\_known\_repeat\_cps;C\_new\_cps;S\_known;S\_new;Valid;Drift\_pct;Drift\_fail};
masked values are empty.

\paragraph{Saturation threshold.} The configuration key \key{saturation\_warn\_frac}
(default 0.90, fraction of full scale, raw ADC peak) is the single saturation
warning threshold for the desktop application, the web client, the exposure
indicator and all calibration procedures. The upper limit of the auto-exposure
target band (\key{calibration\_target\_frac\_hi}) is capped at this value.

\subsection{Lamp library}
Tab \emph{Lamps}: import Avantes \file{.lmp} (tab/space separated, decimal comma
or point, CRLF, optional index column) or CSV; per lamp enter name, serial number,
unit, lower/upper validity limit (HAL-CAL: 380\nm) and intended input optic. The
library is stored in \key{reference\_sources\_file}. A synthetic demo lamp is
built in.

\subsection{Profile management}\label{sec:speccal-profiles}
The tab \emph{Profiles} lists all versions with their status; it provides
activate, export\,/\,import (one profile as a file), delete and
\emph{Copy profile to this device\ldots}.
\begin{itemize}
  \item \textbf{Versions:} each run adds a version; the newest \emph{valid} one is
        the default, older ones stay available.
  \item \textbf{Serial binding:} profiles of another unit of the same type
        (e.g.\ a second HDX) are not shown. Copying is deliberate and recorded in
        the profile (\code{copied\_from}). A back-end that reports no serial
        (PASCO) produces unbound profiles.
  \item \textbf{Wavelength changed:} if the current fingerprint differs from the
        stored one the profile is marked \emph{``Wavelength changed --- recalibrate''}
        and applied only after explicit confirmation.
  \item \textbf{Linearisation changed:} each profile records whether the
        detector nonlinearity correction was active
        (\code{acquisition.nl\_correction}; Ocean HDX:
        \key{ocean\_nonlinearity\_correction}). $S$ and $K$ are per-pixel factors
        measured at one signal level; only the linearisation makes them valid at
        every other level. If the current state differs, the profile is marked
        (state \code{nl\_changed}) and applied only after confirmation. The
        calibration does \emph{not} compensate a missing linearisation. Devices
        without a linearisation (PASCO, LR-2T, Demo) are not checked.
        A confirmation is valid only for exactly the current combination of
        wavelength fingerprint and linearisation state.
  \item \textbf{Migration:} profiles of the previous format become
        \code{relative}, optics \code{unknown}, unbound, and keep the old gain
        rule ($\min(1/S,10)$, gain~1 outside), so their result is unchanged.
        Before the first write in the new schema a backup
        \file{calibration\_profiles.v1.bak.json} is kept. The old way
        ``reference = second measurement'' remains in the tab \emph{Response
        (legacy)}.
\end{itemize}

\subsection{Measuring with a profile}\label{sec:speccal-apply}
Main window and web client run \code{processing.process\_frame()} with identical
inputs (\code{pipeline\_kwargs}), hence identical values. Order:
\begin{enumerate}
  \item \emph{(if a linearity correction is active)} correct each frame directly after
        the driver (\S\ref{sec:linearity});
  \item subtract a \emph{per-pixel} dark --- \emph{mandatory} with a profile,
        independent of the \emph{Dark correction} switch and of \key{dark\_mode},
        not clipped. Source, in this order: the stored dark of this unit at
        exactly the current $t_{\mathrm{int}}$; otherwise the per-pixel model
        $D(t) = b + r\,t$ fitted over all stored darks of the unit (the wizard
        always stores $t_{\mathrm{int}}$ and $t_{\mathrm{int}}/2$; more via
        \emph{Processing $\to$ Stored dark $\to$ Capture dark}, input covered).
        Only if the unit has no stored dark at all, the scalar
        optical-black/parametric estimate is used and the status line shows a
        warning (values not reliable --- the scalar estimate biases the weak
        blue end by tens of percent). The status line names the dark source.
        Without a profile, \emph{Stored dark (per pixel)} uses the same sources;
  \item divide by $t_{\mathrm{int}}$ ($\to$ counts/s);
  \item despeckle and spatial smoothing (if enabled);
  \item multiply by $1/S$ or $K$ (unit factor applied); NaN outside the valid range.
\end{enumerate}
The legacy response gain is not applied in this case. \emph{Y-axis and exports}
carry the unit: counts, counts/s (\key{display\_unit}), relative,
\code{uW/cm2/nm} or \code{W/m2/nm} (\key{irradiance\_unit}); masked ranges are
grey in the plot and empty in CSV. Profile selection: the \emph{Response
correction} drop-down (name $\cdot$ type $\cdot$ version $\cdot$ date) and the
\emph{Calibration status} line show the active profile, its valid range and
warnings. With an absolute profile lux is computed directly from $E(\lambda)$
and \key{radiometric\_calibration\_factor} is ignored; with a relative profile
colorimetry uses the corrected distribution. The web client offers the same
profiles, units and management (\code{/api/calibration/*}); it does
\emph{not} capture calibrations.

\subsection{Detector linearity calibration}\label{sec:linearity}
\paragraph{Why.} $S$ and $K$ are per-pixel factors measured at \emph{one} signal
level. If the detector response is not proportional to the light (LR-2T: about
$+1.5$\,\% between 39 and 78\,\% of full scale), every measurement at another
level is biased and the $t_{\mathrm{int}}/2$ cross check of the spectral
calibration fails (cause \emph{nonlinearity}, \S\ref{sec:speccal-checks}). The
linearity calibration measures this per unit and corrects it at the start of the
pipeline.

\paragraph{When.} Needed for LR-2T and PASCO when the cross check reports a
nonlinearity, or before the first spectral calibration of a unit. It is
independent of the optics and valid per unit (backend and serial number);
repeat it after a repair or a change of the electronics. The Ocean HDX
linearises in the device itself (\key{ocean\_nonlinearity\_correction}); there
only a \emph{check} measurement is made and a stored correction is never applied
on top (no double correction).

\paragraph{Procedure} (tab \emph{Linearity} of the calibration dialog; web
client and API \code{POST /calibration/linearity/runs}, MCP tool
\code{start\_linearity}):
\begin{enumerate}
  \item Illuminate the input with a stable broadband source (halogen lamp, warmed
        up); the reference calibration of a lamp is \emph{not} needed.
  \item Darks are captured at \emph{every} integration time before and after the
        light steps (covering steps as in the spectral wizard).
  \item 6--10 (\key{linearity\_steps}, default 8) integration times are chosen so
        that the raw peak lies between about 10 and 90\,\% of full scale
        (below the saturation level). All frames are taken with the existing
        linearity correction bypassed (raw driver output).
  \item A \emph{reference step} ($\approx50$\,\% FS) is repeated at the start,
        after every third step and at the end; its count rate follows the lamp
        drift, which is divided out of every step (linear interpolation in
        time). A larger lamp drift produces a warning.
  \item Fit, residual check and protocol (PDF/CSV); the record is stored and,
        unless declined, activated.
\end{enumerate}

\paragraph{Model.} For pixel $p$ and step $k$ with net counts
$N = \mathrm{light}-\mathrm{dark}$ (dark interpolated in time):
\[
  \frac{N}{t\,L(\tau)} = R_p\,h(N),\qquad
  h(N)=\exp\!\Bigl(\sum_{j\ge1} d_j\,(N/\mathrm{FS})^{j}\Bigr),\quad h(0)=1 ,
\]
with $R_p$ the linear count rate of the pixel (eliminated per pixel as a
nuisance parameter) and $L$ the lamp factor. The correction is
$\mathrm{counts}_{\mathrm{true}} = f(N) = N/h(N)$: at \emph{low} signal the
corrected value equals the measured one, so the weak end keeps its scale. $f$ is
stored as a polynomial ($d_j$, degree \key{linearity\_degree}, default 3) and as a
monotonic support-point table over the measured range; beyond the range the end
ratio is kept constant.

\paragraph{Application order and why.} The nonlinearity belongs to each single
readout (charge-to-voltage conversion and ADC) and acts on the accumulated
signal (photo charge plus dark current) \emph{above} the electronic offset.
Therefore the correction is applied
\begin{enumerate}
  \item per \emph{frame}, directly after the driver --- before fusion, frame
        averaging and fast-preview scaling (all of these assume linear counts)
        and before the calibration and measurement frame taps;
  \item on the signal above the frame's baseline $b$ (the driver's dark scalar:
        optical black or darkest-pixel estimate):
        $b + f(\mathrm{raw}-b)$ --- the electronic offset itself is not subject to
        the detector nonlinearity;
  \item \emph{before} the dark subtraction; dark frames pass through the same
        correction ($f(x)\approx x$ for small $x$), so light $-$ dark stays
        consistent.
\end{enumerate}
Fast-preview frames scaled by a ratio are corrected at their true level.
Without an active correction nothing changes.

\paragraph{Storage and profiles.} The records are stored in
\file{linearity\_profiles.json} (data directory, \S\ref{sec:datadir}), one list
of records; the active correction is kept per unit. States: \emph{none},
\emph{active}, \emph{off} (stored but switched off), \emph{factory} (HDX, not
applied). Each spectral profile records the linearity state it was made with
(profile tag: active yes/no and record id). If the state now differs, the status
line shows a hint (``linearity correction was on/off when this profile was
made\ldots recalibrate for exact values''); the profile is not blocked. Protocols
and exports state the linearity correction explicitly as \emph{on}, \emph{off} or
\emph{n/a}.

\subsection{Limits}
\begin{itemize}
  \item Below the validity limit of the reference source (HAL-CAL: about 380\nm)
        there is no calibration; on the HDX (display from 350\nm) the range
        350--380\nm stays masked.
  \item Stray light from the strong red/NIR part of a halogen lamp raises the
        uncertainty in the blue.
  \item Bare fibre: for spatially or angularly inhomogeneous sources the spectrum
        depends on alignment (not a calibration error).
  \item Absolute irradiance only with a defined entrance area (CC, sphere as
        collector); absolute radiance only with a bare fibre or an objective in
        front of an extended source (\S\ref{sec:radiance}); no luminous or radiant
        flux.
  \item $S$ and $K$ are valid only for the wavelength calibration of their
        fingerprint and for the optics configuration and unit they were made on.
\end{itemize}

\section{Spectral radiance}\label{sec:radiance}
Optics that look at an extended source with a limited field of view --- a
microscope objective, a bare fibre in front of a luminous surface --- measure
\emph{radiance} $L(\lambda)$, not irradiance. The absolute radiance calibration
is traced back to the existing absolute irradiance calibration with the cosine
corrector (CC): an integrating sphere with a Lambertian exit port is
characterised with the CC and then serves as a radiance reference.

\subsection{Measurement quantities}
The measurement quantity is a property of every reference source and profile
(field \code{quantity}):
\begin{longtable}{@{}p{2.6cm}p{5.4cm}p{6.2cm}@{}}
\toprule \textbf{Quantity} & \textbf{Units} & \textbf{Photometric value}\\ \midrule\endhead
\code{irradiance} & W/(m$^2$\,nm), mW/(m$^2$\,nm), $\mu$W/(cm$^2$\,nm) &
  illuminance $E_v = 683\,\mathrm{lm/W}\int E\,V\,\mathrm d\lambda$ [lx]\\
\code{radiance} & W/(m$^2$\,sr\,nm), mW/(m$^2$\,sr\,nm), $\mu$W/(cm$^2$\,sr\,nm) &
  luminance $L_v = 683\,\mathrm{lm/W}\int L\,V\,\mathrm d\lambda$ [cd/m$^2$]\\
\bottomrule
\end{longtable}
Units convert only within the same quantity. Profiles and library sources
stored before this field existed are irradiance (migration on load; the
profile store is rewritten with \code{quantity} on the next save). The display
unit setting (\key{irradiance\_unit}) selects the prefix; a radiance profile
uses the radiance unit with the same prefix.

\paragraph{Admissible input optics.}
\begin{longtable}{@{}p{4.2cm}p{10.0cm}@{}}
\toprule \textbf{Type / quantity} & \textbf{Input optics}\\ \midrule\endhead
relative (either quantity) & CC, bare, sphere, objective\\
absolute irradiance & CC, sphere (as collector)\\
absolute radiance & bare, objective\\
\bottomrule
\end{longtable}
The same rule (\code{calibration\_profiles.admissible}) applies in the desktop
wizard, the web dialog, \code{/api/v1} and the MCP tools.

\subsection{The sphere as a radiance reference}
A Lambertian disk of radius $r$ and uniform radiance $L$ produces on its axis,
at the distance $d$ from the disk plane, the irradiance
\[
  E(d) = \pi L\,\frac{r^2}{r^2+d^2}
  \qquad\Longrightarrow\qquad
  L = E\,\frac{r^2+d^2}{\pi r^2}.
\]
The plane of the disk is the knife edge of the port aperture. For the printed
sphere (exit port diameter 14.00\,mm, knife-edge plane 11.00\,mm below the top
surface of the housing) the distance is
\[
  d_i = a + h_i + c ,
\]
with $a$ = knife-edge plane $\to$ housing top (measured, default 11.00\,mm),
$h_i$ = housing top $\to$ CC support surface at position $i$ (spacers) and
$c$ = CC reference plane relative to its support surface (default 0; positive
= farther from the port). Radius and depth are measured at the part and
entered; their standard uncertainties $u(r)$, $u(d)$ enter the uncertainty
budget.

\paragraph{Run.}
Prerequisite: an \emph{active} absolute irradiance profile with input CC for the
connected unit, valid with the current wavelength calibration and
linearisation; otherwise the run is refused with a message. Sequence:
CC on the port at the smallest distance $\to$ integration time (auto exposure
at this, the brightest, position, kept for the whole run) $\to$ dark before
$\to$ $E(\lambda)$ at $N\ge 3$ distances (the distance $h_i$ is entered for
every position) $\to$ repeat of the first distance (source drift) $\to$ dark
after. Every light capture is corrected with the dark interpolated in time;
$E$ is the count rate times the CC profile's $K$, masked outside its valid range
and below the SNR limit. The first position uses the mean of its capture and
the repeat (mid-run level).

\paragraph{Evaluation per wavelength.}
\begin{itemize}
  \item $L_i = E_i\,(r^2+d_i^2)/(\pi r^2)$ for every distance.
  \item Fit of $E(d) = \pi L\,r^2/(r^2+(d+d_0)^2)$ with $L(\lambda)$ free per
        wavelength and a common offset $d_0$ (relative residuals, i.e.\ in
        $\ln E$), overall and per 50-nm band. $d_0$ absorbs a constant error of
        the reference planes. If $|d_0|$ is below \key{sphere\_d0\_max\_mm}
        (default 1.0\,mm) the fitted $L$ is used, else the mean of $L_i$
        (nominal geometry) and a warning.
  \item Consistency: relative spread (standard deviation / mean) of $L_i$ over
        the distances --- with the geometry actually used ($d_i+d_0$) --- per
        50-nm band and overall; the check passes when all values are at most
        \key{sphere\_consistency\_max\_pct} (default 2\,\%). A clearly
        non-uniform or non-Lambertian port, a wrong radius or wrong distances
        show up here. A \emph{slightly} non-Lambertian port
        ($L\propto\cos^n\theta$ with small $n$) cannot be told apart from an
        offset of the reference planes on the axis: $d_0$ absorbs it and the
        spread stays small. Therefore $d_0$ always enters the uncertainty
        (below), and a warning is given when $|d_0|$ exceeds twice the
        distance uncertainty $u(d)$.
  \item Drift: p95 of $|E_{\mathrm{repeat}}/E_1-1|$, the ratio smoothed over
        the band width \key{sphere\_band\_nm} (a source drift is spectrally
        smooth, per-pixel noise is not), against
        \key{sphere\_drift\_max\_pct} (default 1\,\%).
\end{itemize}

\paragraph{Uncertainty (simplified GUM, $k=1$).}
\[
  \frac{u^2(L)}{L^2} = (c_r\,u_r)^2 + (c_d\,u_d)^2 + \frac{s^2}{N}
     + \frac{\delta_{\mathrm{drift}}^2}{3} + u_{\mathrm{CC}}^2
     + \frac{(c_d\,d_0)^2}{3} ,
\]
\[
  c_r = \overline{\frac{2d_i^2}{r\,(r^2+d_i^2)}}, \qquad
  c_d = \overline{\frac{2d_i}{r^2+d_i^2}},
\]
with $s$ the relative spread of $L_i$ at this wavelength, $\delta_{\mathrm{drift}}$
the mean relative drift (rectangular distribution) and $u_{\mathrm{CC}}$ the
relative standard uncertainty of the CC calibration (input, default
\key{sphere\_cc\_uncertainty\_pct} = 3\,\%). The inputs are treated as
uncorrelated. The fitted offset is carried as a rectangular contribution of
half-width $c_d\,|d_0|$; for a $\cos^n$ port this covers the bias of $L$ at
$k=1$ (verified for $n\le 1$ in the tests). The cosine error of the CC at the
irradiation angles of the run (up to $\arctan(r/d)$, about 32$^\circ$ at
$d=11$\,mm) is part of $u_{\mathrm{CC}}$ and not modelled separately. The
protocol lists every component, the combined $u$ per band and $U=2u$.

\paragraph{Result.}
A library source with \code{quantity = radiance}, unit $\mu$W/(cm$^2$\,sr\,nm),
valid range = the largest contiguous range inside the CC profile's valid range
in which $E>0$ at every distance, smoothed like a calibration
(\key{calibration\_smooth\_px}). Its metadata hold the geometry, date, device,
CC profile id/version, consistency, drift and uncertainty; the per-point
standard uncertainty is stored with the values. Protocol PDF and CSV.

\subsection{Absolute radiance calibration}
The spectral calibration wizard accepts radiance sources: type absolute,
input bare or objective, reference = the characterised sphere. Result: profile
\code{absolute}, \code{quantity = radiance},
$K$ in $\mu$W/(cm$^2$\,sr\,nm) per count/s (plus the derived relative profile).
\textbf{The source must fill the field of view of the optics completely and
uniformly}: sphere port under the objective, focus on the port plane; a bare
fibre close above the port with its acceptance cone inside the port. The
derivation (\S\ref{sec:speccal-derive}) accepts absolute radiance profiles as
the known optics and derives relative profiles with the same quantity.

\subsection{Measuring radiance}
With an active radiance profile the display, exports, \code{/api/v1} and MCP
report the quantity and unit; the photometric value is the luminance in cd/m$^2$
instead of the illuminance in lx (desktop Color tab and web).

\subsection{Limits}
\begin{itemize}
  \item The disk formula assumes a uniform Lambertian port; the consistency
        check reveals deviations but does not correct them.
  \item The radiance scale inherits the CC calibration (reference lamp,
        cosine response of the CC); its uncertainty is an input, not measured.
  \item The field of view of the radiance optic must lie entirely inside the
        uniform part of the port; vignetting or a field of view larger than the
        port gives too low values.
  \item Polarisation and the angular distribution inside the acceptance cone
        of the radiance optic are not modelled.
\end{itemize}

\section{Signal-processing pipeline}\label{sec:pipeline}
All of the following live in \file{processing.py} / \file{fusion.py} and run
\emph{after} the driver, so they apply uniformly to every device.

\subsection{Frame averaging}
\key{frames\_to\_average} ($N$) averages the last $N$ frames before display.
Averaging reduces random noise by $\sqrt{N}$ without touching spectral resolution
(the spectrum is static); it is the preferred noise tool.

\subsection{Hot-pixel / despeckle}
\key{hot\_pixel\_filter} runs a small median despeckle to remove isolated bright
pixels; \key{smoothing\_width} sets its window.

\subsection{Fast Preview (simple model)}\label{sec:fp}
Fast Preview shortens the hardware exposure to \key{fast\_preview\_short\_pct} of
the main integration time, reads frames back-to-back, and scales the net signal
back up:
\[
\text{ratio} = \frac{t_{\text{long}}}{t_{\text{short}}}, \qquad
\text{out} = \mathrm{clip}\big((\text{pixels}-\text{dark})\cdot\text{ratio},\,0,\,
\text{sat}-\text{dark}\big) + \text{dark}.
\]
There is no long/short interleave. The scaling lives in the drivers (it needs the
device saturation and dark model) --- the one deliberate exception to ``no
processing in drivers''. Per device: PASCO/LR-2T trigger at $t_{\text{short}}$; the
HDX uses software-trigger mode 0, sets the short exposure once, settles past the
stale first metadata frame, then streams and scales.

\subsection{Adaptive temporal smoothing (\file{fusion.py})}
An optional per-pixel temporal filter (the ``Smoothing'' section). It smooths
\emph{stable} pixels heavily and backs off instantly where the signal changes, so
peaks keep their shape and a brand-new peak appears in a single frame; it never
mixes across wavelength. Parameters: \key{fusion\_smoothing} (0--1 strength on
stable pixels), \key{fusion\_change\_sigma} (deviation at which it backs off),
\key{fusion\_noise\_floor} / \key{fusion\_noise\_gain} (the read- and shot-noise
model), and the emit-rate controls \key{fusion\_emit\_hz/min/max}. Off =
pass-through.

\subsection{Spatial (pixel-window) smoothing}
\key{spatial\_smoothing} applies a moving average of \key{spatial\_smoothing\_width}
pixels along the wavelength axis (\code{processing.apply\_spatial\_smoothing}).
Unlike the temporal filter it removes fixed-pattern structure (PRNU/etaloning), at
the cost of broader, lower peaks --- keep the window below the narrowest peak's
FWHM. Off by default.

\subsection{Performance reality}\label{sec:perf}
The \emph{new-data} rate is $\approx 1/t_{\text{short}}$. On the HDX a fixed
$\sim$25\,ms host per-frame overhead (USB read + processing) sets a floor: below
$t_{\text{short}}\approx 25\,$ms the rate is host-limited, not integration-limited.
Set \code{FP\_DEBUG=1} to log per-frame $\Delta t$, new-vs-repeat (payload hash) and
measured Hz against the $1/t_{\text{short}}$ ceiling. The emit timer can refresh the
canvas faster but cannot create new measurements.

\section{The reference-spectrum library}\label{sec:refspectra}
\file{reference\_spectra.csv} holds 25 illuminant and lamp spectra used as scope
background overlays, as Demo-device sources, and for teaching. It is generated
automatically by \code{spectrometer\_core.py} if absent (regenerated when the
``Solar AM1.5G'' column is missing --- a version sentinel).

\subsection{File format}
A semicolon-delimited table; the first column is \code{Wavelength\_nm}, every
further column is one named spectrum:
\begin{quote}\ttfamily\scriptsize
Wavelength\_nm;Hydrogen (H);Mercury (Hg);Sodium (Na);Neon (Ne);Argon (Ar);\\
Helium (He);\dots;Fluorescent 2-band;Fluorescent 3-band;\dots;LED White Cool;Solar AM1.5G
\end{quote}
The bench file spans 300--1100\nm in 0.5\nm steps (1601 rows). Columns include
discharge lamps (H, Hg, Na, Ne, Ar, He, Kr, Xe, Cd, Ne--Ar mix), fluorescent
types (2/3/4-band), a full LED set (violet$\to$red plus warm/neutral/cool white)
and Solar AM1.5G.

\subsection{How spectra are read}
Two loaders, both semicolon-aware:
\begin{itemize}
  \item \code{spectrometer\_core.load\_reference\_library(target\_wavelengths)} ---
        parses the CSV into \code{name $\to$ spectrum}. If a target wavelength axis
        is given (the connected device's), each column is resampled onto it with
        \code{np.interp} (zero outside the source range) and normalised to
        $0\ldots1$; otherwise the native wavelength column is returned. This drives
        the ``Reference library'' overlay selector.
  \item \code{\_device\_demo.\_load\_csv\_spectrum(name, wl)} --- the Demo device's
        loader: it matches a column by name (partial match allowed), reads the
        \code{(wavelength, value)} pairs and resamples onto the demo's pixel axis,
        again zero outside the source range, then peak-normalises (max $=1$).
\end{itemize}

\section{The Demo (virtual) device}\label{sec:demo}
\file{\_device\_demo.py} is a hardware-free back-end registered as

\begin{itemize}

  \item \textbf{Difference} --- shows live $-$ frozen snapshot (signed ADC,
        magenta); freeze a reference first.
  \item \textbf{Peak-hold} --- a per-pixel running maximum (yellow), like an
        equaliser peak meter; toggle to re-arm.
  \item \textbf{Persistence} --- fading echoes of the last few frames,
        oscilloscope-style.
  \item \textbf{CSV background reference} --- load a 2-column
        (wavelength, intensity) CSV, drawn cyan and normalised to the current Y max;
        or pick a library spectrum via ``Reference library''.
\end{itemize}

\subsection{Display modes}\label{sec:displaymodes}
The \emph{Display} selector (scope and heatmap; web client identical;
\key{display\_mode}, API/MCP \code{display\_mode}) chooses \emph{what is plotted}.
It does not change the data: all evaluations (colorimetry, CRI, TM-30, filter
analysis, peaks) always run on the \emph{corrected} data of the pipeline, and
CSV/PDF exports are independent of the display mode (they carry the mode and
unit as information in the header).
\begin{longtable}{@{}p{2.9cm}p{11.3cm}@{}}
\toprule \textbf{Mode} & \textbf{Definition}\\ \midrule\endhead
Raw ADC & Counts without calibration profile (dark correction and smoothing as
  configured). Without a profile identical to the previous display.\\
Corrected counts & Corrected rate $\times\,t_{\mathrm{int}}$, normalised so that
  \emph{Corrected = Raw at the pixel of maximum sensitivity} (smallest correction
  factor). The familiar ADC scale is kept: in the most sensitive region corrected
  and raw counts agree, elsewhere the curve shows what the detector would have
  counted with a flat response. Default with an active profile.\\
Normalised & Maximum $=1$ over the valid (finite) pixels.\\
Count rate & Counts per second (with a profile: corrected rate on the same
  normalisation as \emph{Corrected counts}).\\
Absolute & Spectral irradiance in the active unit; only with an absolute profile.\\
Auto & \emph{Corrected counts} with an active v2 profile, else \emph{Count rate}
  if \key{display\_unit} is \code{counts\_per\_s}, else \emph{Raw ADC}.\\
\bottomrule
\end{longtable}
\paragraph{Availability.} Without a profile: Raw ADC, Normalised, Count rate.
With a relative profile additionally Corrected counts; with an absolute profile
also Absolute. A requested mode that is not available falls back (Absolute
$\to$ Corrected $\to$ Raw).

\paragraph{Exposure level.} In corrected views the drive level of the detector
is no longer visible from the curve. The scope therefore keeps an exposure
indicator in \emph{raw ADC} (peak counts, percent of full scale, saturated pixel
count; bar or faint raw curve), independent of the display mode, with a
saturation warning at the saturation level.

\paragraph{Y limits.} Manual Y limits are stored \emph{per display mode}
(\key{y\_limits\_by\_mode}; heatmap: \key{heatmap\_limits\_by\_mode}); calibrated
units use auto-scaling by default, and the axis is rescaled when the mode is
switched. The heatmap upper limit follows the same logic.

\paragraph{Readout.} The hover and top-bar readout shows the \emph{active unit}
(not a fixed ``ADC'') and ``--'' instead of ``nan'' for masked pixels (desktop
and web).

\subsection{Heatmap (waterfall) tab}
A time-lapse image: each new spectrum becomes one coloured row.
\textbf{The newest frame is at the bottom and history scrolls upward}
(Fig.~\ref{fig:fig_waterfall.pdf}); this direction is unified across the desktop,
the web heatmap and the replay player. Hovering shows a crosshair with the
wavelength, ADC value and frame age, and drives the top-bar readout.

\fig{fig_waterfall.pdf}{0.62}{Waterfall convention: row 0 (newest) at the bottom,
older rows above. A drifting peak therefore appears to rise.}

\subsection{Color $\cdot$ CRI tab}
Four sub-tabs share one measurement. \emph{Overview} shows colorimetry cards;
\emph{CIE 1931} the chromaticity diagram with a MacAdam ellipse; \emph{Color
Rendering} the CRI radar and per-sample bars; \emph{TM-30 $\cdot$ CQS} the TM-30
results. Every card has a tooltip with its definition; the metrics themselves are

\fig{fig_cie_locus.pdf}{0.6}{The Planckian locus computed by \code{color\_science}

\paragraph{CCT validity (off-locus guard).}\label{sec:cct-guard}
CCT is only physically meaningful for near-white sources close to the Planckian
locus. The engine reports a number only when it is finite, within
1000--25000\,K \emph{and} $|$Duv$|\le 0.05$ (the ANSI/IES whiteness limit);
otherwise CCT is shown as ``\,--\,''. This prevents absurd values (McCamy's
approximation diverges for off-locus chromaticities). $x$, $y$, Duv and the
peak/dominant wavelengths are still reported, because they correctly describe even
an exotic source.

\subsection{Replay tab (web)}
Loads a heatmap CSV exported from the app (or a single-spectrum CSV) and replays it
as a waterfall with a transport (play/scrub/speed/loop). \textbf{The current frame
is drawn at the bottom with earlier frames stacked above}, matching the live
heatmap.

\subsection{Filter tab}\label{sec:filter}
Characterises an optical filter by ratioing two spectra.
\begin{enumerate}
  \item With the \emph{light source only} (no filter in the beam) press
        \textbf{Set baseline}. The app averages \key{filter\_baseline\_frames}
        frames (default 16) into the 100\,\% reference; the button shows
        ``Averaging\,\dots\,$k$/$N$''. Averaging the static reference cuts its noise
        $\sim\!\sqrt{N}$ without losing resolution --- and that noise would
        otherwise enter every later $T=\text{sample}/\text{reference}$.
  \item Insert the filter. The tab plots live transmission
        $T(\lambda) = \text{sample}/\text{reference}$ in percent and computes the
        metrics.
\end{enumerate}
Where the reference is below 2\,\% of its maximum, $T$ is masked (the data is
genuinely uncertain there). Optional display-only smoothing
(\key{filter\_display\_smoothing}, default off) calms the \emph{drawn} curve only;
all metrics always run on the raw transmission.

\fig{fig_filter_example.pdf}{0.98}{A band-pass example. Left: transmission with the
50\,\% points giving FWHM. Right: the same as optical density
$\mathrm{OD}=-\log_{10}T$, which makes the blocking floor readable.}

Dominant $\lambda$ & Where a line from the white point through the source colour meets the spectral locus.\\

FWHM & Full width at half maximum of the main peak (a bandwidth measure).\\
Purity & Excitation purity --- 0\,\% = white, 100\,\% = monochromatic.\\
S/P & Scotopic/Photopic ratio --- relates rod (night) to cone (day) sensitivity; higher favours low-light efficiency.\\

\section{Remote access}\label{sec:remote}
The application can serve its web interface and the REST API itself. Nothing is
reachable from the network unless this is switched on; the default is the local
machine only.

\subsection{Desktop panel}
The sidebar section \emph{Remote access} (\file{gui\_remote.py}) contains:
\begin{itemize}
  \item \textbf{Remote access} switch --- starts or stops the server (uvicorn in a
        background thread, \file{server\_runner.py}) on the running engine. If the
        port is busy or the start fails, the switch returns to off and a message
        names the reason. The state is stored (\key{remote\_enabled}); the server
        starts again with the app.
  \item \textbf{Port} (1024--65535, \key{remote\_port}).
  \item \textbf{Access}: \emph{Local only (127.0.0.1)} or \emph{LAN (all
        interfaces)}. LAN mode forces the token and shows a hint: the connection
        is unencrypted HTTP; use a TLS reverse proxy outside the lab.
  \item \textbf{Require token locally} --- also check the token on a local bind
        (\key{remote\_require\_token\_local}).
  \item \textbf{Token} (masked): \emph{Show}\slash\emph{Hide}, \emph{Copy},
        \emph{Renew}. Renewing asks for confirmation, invalidates the old token and
        restarts a running server.
  \item \textbf{URL} with \emph{Copy URL}.
  \item \textbf{Control} line (who holds control, \S\ref{sec:control}), the running
        remote job, and the buttons \emph{Cancel remote job} and
        \emph{Revoke control}.
\end{itemize}

\subsection{Status bar, locking and Cancel}\label{sec:control}
Exactly one party controls the instrument: \code{local} (the desktop),
\code{web} (a browser) or \code{remote:<client>} (REST/MCP; client name from the
header \code{X-Client-Id}). Settings that alter the acquisition (exposure,
averaging, pause, dark, Fast Preview, \dots) and all jobs need control.
\begin{itemize}
  \item A running job holds control until it ends; a client may also take an
        explicit lease (\code{POST /api/v1/control}).
  \item While a remote party holds control, the desktop disables its control
        sidebar, the header controls and the Connect button. A local change
        attempt shows \emph{Remote control active}.
  \item The status bar shows \emph{Remote: <owner> $\cdot$ <reason>} (and, during a
        job, \emph{Remote job <kind> <n>\,\%}, or the pending user step) with the
        button \textbf{Cancel remote}: it cancels the job and revokes the lease; the
        desktop controls are released at once.
  \item Over the API a conflicting steering command is answered with HTTP~409
        (\code{control\_busy}).
\end{itemize}

\subsection{Headless operation}
\begin{quote}\ttfamily\small
python PS-2600A\_Pro.py --headless [--host H] [--lan] [--port P]\\
\hspace*{2em}[--token T] [--require-token] [--no-connect] [--backend NAME]
\end{quote}
No Qt module is imported on this path, so it runs on a machine without PyQt6
(Raspberry Pi, lab PC without display). Defaults: bind \code{127.0.0.1}; \code{--lan}
binds all interfaces and makes the token mandatory; port from \key{remote\_port};
token from \key{remote\_token}, generated and stored if empty; the first device of
the first backend is connected unless \code{--no-connect} (\code{--backend}
selects another backend, for example \emph{Demo (virtual)}). The start banner prints
the URL, the \code{/docs} URL and the token. \code{python web\_server.py} still
works and forwards to the same server.

The program is started from Python only (virtual environment,
\code{pip install -r requirements.txt}); there is no packaged executable.
\code{--data-dir PATH} selects the data directory (\S\ref{sec:datadir}).

\subsection{Token and security}
For a local bind the token is optional; for LAN it is always required. It is sent as
\code{Authorization: Bearer <token>}; the browser takes it from
\code{http://<host>:8000/?token=<token>} (stored in the browser, removed from the
address bar); the WebSocket accepts \code{?token=}. Without a valid token the web
page stays read-only (live display and display-only settings), and every steering
endpoint answers 401. Read-only endpoints do not need the token.

\medskip\noindent\textbf{Security notes.}
LAN access is plain HTTP: anyone on the network can read the token. Use it only in
a trusted lab network, or put a reverse proxy with TLS (nginx, Caddy) in front. Do
not expose the port to the internet. Renew the token if it leaked. One device is
opened by one engine, so the desktop app and a separate headless server cannot run
on the same device at the same time.

Measurement, series, dark capture, calibration run and derivation are jobs with an
ID, progress, message and result. Status:
\code{queued} $\to$ \code{running} $\to$ \{\code{done}, \code{failed},
\code{cancelled}\}, with \code{waiting\_for\_user} whenever a physical step is
needed (cover or uncover the light path, swap optics); the job's \code{prompt}
names the step. After the user has done it, \code{POST /jobs/\{id\}/continue}
resumes the job; \code{POST /jobs/\{id\}/cancel} ends it at any time. A job holds
control while it runs (\S\ref{sec:control}). Calibration protocols (PDF\slash CSV) are
fetched from \code{/calibration/runs/\{job\}/protocol}.

\section{MCP server \& Claude plugin}\label{sec:mcp}
The MCP server (\file{mcp\_server/}, official Python SDK \code{mcp>=2.3}, stdio
transport) lets Claude operate the instrument. It is a thin layer over the REST API:
it talks to the application only over HTTP (\code{httpx}), imports neither the engine
nor PyQt, and therefore works with the desktop app, with a headless server and over
the network. Install the optional packages with
\code{pip install "mcp>=2.3" httpx} (Python 3.10+).

\subsection{Limits}
There are no deleting tools (no removal of profiles, dark spectra or lamps). Every
tool answer is at most 8\,KB of JSON; longer content is shortened and marked
\code{"truncated": true}, full data is written to files in \code{SPECTRO\_DATA\_DIR}
and the path is returned. The server writes files only there. A user step of a job
(cover\slash uncover) is reported as \code{waiting\_for\_user}; the assistant must ask
the user and call \code{continue\_job} only after the user confirmed.

\section{Data directory \& migration}\label{sec:datadir}
Runtime data never lives in the program folder (\file{data\_paths.py}, Qt-free).
Default locations:
\begin{itemize}
  \item Windows: \file{\%APPDATA\%\textbackslash PS-2600A\textbackslash}
  \item macOS: \file{\textasciitilde/Library/Application Support/PS-2600A/}
  \item Linux: \file{\$XDG\_CONFIG\_HOME/ps-2600a/} (default
        \file{\textasciitilde/.config/ps-2600a/})
\end{itemize}
\textbf{Override} (highest priority first): the command-line option
\code{--data-dir PATH}, then the environment variable \code{PS2600A\_DATA\_DIR}.

\paragraph{Contents.} \file{spectrometer\_config.json} (settings),
\file{calibration\_profiles.json} (and \file{calibration\_profiles.v1.bak.json}),
\file{dark\_spectra.json}, \file{reference\_sources.json} (lamp library),
\file{linearity\_profiles.json}, the folders \file{protocols/} (calibration and
linearity protocols) and \file{backup/}, and the migration records
\file{migration.json} and \file{migration.log}. Relative file names in the
configuration (e.g.\ \key{calibration\_profiles\_file}) resolve into the data
directory.

\paragraph{One-time migration.} If the data directory has no
\file{migration.json}, the files found in the program folder (the runtime files
above, \file{*.bak.json}, \file{old\_calib\_data\_*.json}, earlier calibration and
linearity protocols) are \emph{copied}, never moved. An existing file in the data
directory is never overwritten; the version from the program folder is kept
beside it as \file{<name>.from-program-dir-<timestamp>.json}. Every source file
is also copied to \file{backup/migration-<timestamp>/}. The result is written to
\file{migration.json} (marker) and appended to \file{migration.log}. Afterwards
the program reads and writes only the data directory; the originals in the
program folder stay untouched. \code{PS2600A\_SKIP\_MIGRATION=1} skips the
migration.

\paragraph{Templates and repository.} The repository contains only
\file{*.example.json} templates; the real data files are listed in
\file{.gitignore}.

\paragraph{Export folder.} Exports default to
\file{<Documents>/PS-2600A} (\key{export\_dir}), not to the program folder.

\section{Extending: adding a new device}
\begin{enumerate}
  \item Clone the closest \file{\_device\_*.py} (they are structurally parallel).
  \item Set the class attributes (\code{PIXEL\_COUNT}, \code{WL\_MIN/MAX\_NM},
        \code{SUPPORTS\_OB}, \code{SUPPORTS\_FAST\_PREVIEW}, \code{RESPONSE\_TABLE})
        and implement the methods in the documented order.
  \item In \code{connect()} set \code{min\_integration\_us} /
        \code{max\_integration\_us} (and \code{serial} if available).
  \item Emit finished frames via \code{on\_frame(\dots, kind="standard", ratio=1.0)};
        if you implement Fast Preview, do the short-exposure scaling in the driver.
  \item Register the class in \code{device\_manager.build\_registry()} and add any
        new config keys to \code{DEFAULT\_CONFIG}.
\end{enumerate}
Keep all signal/science work out of the driver --- it belongs in
\file{processing.py} / \file{color\_science.py} / \file{filter\_analysis.py}.

\section{Troubleshooting \& known non-issues}
\begin{itemize}
  \item \textbf{CCT shows ``--''} --- the source is off-locus ($|$Duv$|>0.05$);
        this is intended, not a fault. $x,y$ and the wavelengths are still valid.
  \item \textbf{Low FPS at long exposure} --- exposure-limited physics
        (new-data $\approx 1/t_{\text{short}}$), not a bug (\S\ref{sec:perf}).
  \item \textbf{Response correction does nothing} --- the dropdown is on
        \emph{None}, or \emph{Device default} is hidden because the driver ships no
        \code{RESPONSE\_TABLE} (LR-2T / HDX). Measure a profile in the response
        wizard, or select one.
  \item \textbf{Corrected spectrum has a lifted noise floor / edge spikes} --- the
        response reference was a line/band source (the wizard warns below 60\,\%
        coverage). Use a smooth broadband lamp; a banded source carries no
        information in its gaps.
  \item \textbf{TM-30/CQS sub-tab missing or slow} --- install colour-science; on a
        slow host it is throttled by design. CRI/CIE/other reports are unaffected.
  \item \textbf{Spectrum mirrored (LR-2T)} --- set \key{lr2t\_flip\_pixels} true.
  \item \textbf{Filter plot looks noisy} --- raise \key{filter\_baseline\_frames}
        (average a cleaner reference) rather than smoothing $T(\lambda)$, which would
        distort edge/FWHM/OD metrics.
\end{itemize}
